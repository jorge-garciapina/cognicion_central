EJEMPLOS GUÍA — FUENTE DE INSTANCIACIÓN CONTEXTUAL
Basados en el planteamiento formal previo
================================================================================

PROPÓSITO DE ESTE DOCUMENTO
Estos ejemplos no intentan agotar el modelo.
Su función es servir como guía operativa para ver cómo se usa el planteamiento en
casos concretos.

Cada ejemplo conserva la misma arquitectura mínima:

1) Fuente estructural
2) Invariantes
3) Dimensiones intensionales
4) Vector de instanciación
5) Región de salida dominante
6) Adaptador
7) Manifestación material
8) Evidencia / validación

La intención es mostrar que el modelo no es solo una definición abstracta,
sino una máquina de construcción, análisis y traducción.

EJEMPLO GUÍA 1
CREACIÓN DE CONTENIDO DIGITAL — PIEZA DE CAPTACIÓN INICIAL
================================================================================

1) Fuente estructural
Nombre:
Sistema de contenido analítico de estrategias públicas

Identidad de la fuente:
Fuente diseñada para producir piezas que convierten fenómenos públicos en
lecturas estructurales de alto interés, manteniendo una identidad de:
- lectura analítica,
- precisión conceptual,
- densidad estructural,
- legibilidad pública,
- vocación de continuidad.

La fuente no es:
- un video aislado,
- una plataforma,
- una noticia particular,
- ni un solo tema político.

La fuente es:
la entidad estructural que vuelve posible una familia de piezas compatibles.

------------------------------------------------------------
2) Invariantes
- Toda salida debe leer un fenómeno como estructura y no como anécdota suelta.
- Debe existir una promesa cognitiva clara.
- Debe existir algún grado de sorpresa o reencuadre.
- La identidad del sistema debe sentirse analítica, no banal.
- La pieza debe ser compatible con continuidad futura.

------------------------------------------------------------
3) Dimensiones intensionales relevantes
d1 = tipo de fenómeno
d2 = grado de controversia
d3 = nivel de tecnicidad
d4 = intensidad del gancho inicial
d5 = densidad conceptual
d6 = ritmo narrativo
d7 = compatibilidad algorítmica
d8 = continuidad seriable
d9 = nivel de polarización tolerado
d10 = claridad del cierre

------------------------------------------------------------
4) Vector de instanciación
Caso particular:
pieza para detener scroll y abrir serie sobre estrategia política

V1 = (
  tipo_de_fenomeno = maniobra discursiva pública,
  grado_de_controversia = medio-alto,
  nivel_de_tecnicidad = medio,
  intensidad_del_gancho = alta,
  densidad_conceptual = media,
  ritmo_narrativo = rápido,
  compatibilidad_algoritmica = alta,
  continuidad_seriable = alta,
  polarizacion_tolerada = media,
  claridad_del_cierre = media
)

------------------------------------------------------------
5) Región de salida dominante
Región dominante:
Captación inicial + retención temprana + apertura de serie

Lectura:
La configuración no apunta todavía a vender ni a enseñar a profundidad.
Su región dominante es:
- detener desplazamiento,
- activar curiosidad,
- abrir una secuencia futura.

------------------------------------------------------------
6) Adaptador
Adaptador seleccionado:
Adaptador de reel corto para plataforma de descubrimiento

Lo que traduce:
- densidad media -> lenguaje accesible
- ritmo rápido -> frases cortas
- controversia media-alta -> gancho inicial fuerte
- continuidad seriable -> cierre abierto

------------------------------------------------------------
7) Manifestación material
Pieza posible:
Reel de 35 segundos

Estructura de salida:
- Hook:
  “La mayoría vio una declaración política.
   Lo que realmente ocurrió fue una maniobra de reposicionamiento.”
- Desarrollo:
  “No cambió el mensaje por error.
   Cambió el marco desde el cual quería ser leído.”
- Cierre:
  “Y ese detalle cambia completamente cómo debe analizarse el caso.
   En la siguiente pieza te muestro el mecanismo.”

------------------------------------------------------------
8) Evidencia / validación
Se valida correctamente si:
- detiene atención inicial,
- produce comentarios del tipo “no lo había pensado así”,
- sostiene continuidad hacia la siguiente pieza,
- conserva identidad analítica.

Falla si:
- la pieza se vuelve solo polémica vacía,
- pierde lectura estructural,
- o ya no parece provenir de la misma fuente.

EJEMPLO GUÍA 2
CREACIÓN DE CONTENIDO DIGITAL — PIEZA DE CONVERSIÓN RELACIONAL
================================================================================

1) Fuente estructural
Nombre:
Sistema de contenido de profundización estratégica con salida a interacción privada

Identidad de la fuente:
Fuente que no busca solo informar, sino mover a una parte de la audiencia hacia
una relación más cercana mediante:
- contenido público de alto valor,
- filtrado de interés real,
- oferta metodológica,
- entrada a conversación privada.

------------------------------------------------------------
2) Invariantes
- La pieza debe mostrar valor real antes del CTA.
- El CTA no puede sentirse arbitrario.
- La relación entre pieza pública y capa privada debe ser coherente.
- La salida privada debe percibirse como profundización, no como truco barato.
- Debe existir un criterio de filtrado implícito o explícito.

------------------------------------------------------------
3) Dimensiones intensionales
d1 = complejidad del caso
d2 = aplicabilidad práctica
d3 = deseo de replicabilidad
d4 = claridad del CTA
d5 = nivel de filtrado relacional
d6 = densidad metodológica prometida
d7 = fricción de entrada
d8 = legitimidad epistémica percibida

------------------------------------------------------------
4) Vector de instanciación
V2 = (
  complejidad_del_caso = media,
  aplicabilidad_practica = alta,
  deseo_de_replicabilidad = muy_alto,
  claridad_del_CTA = alta,
  filtrado_relacional = medio,
  densidad_metodologica_prometida = alta,
  friccion_de_entrada = baja,
  legitimidad_epistemica = media-alta
)

------------------------------------------------------------
5) Región de salida dominante
Región dominante:
Conversión relacional + conversión metodológica

Lectura:
La pieza ya no busca solo alcance.
Busca seleccionar a quienes quieren el mecanismo detrás de la lectura pública.

------------------------------------------------------------
6) Adaptador
Adaptador:
Video corto con CTA de DM

Traducción:
- aplicabilidad alta -> ejemplo concreto
- replicabilidad alta -> promesa de procedimiento
- fricción baja -> CTA simple
- filtrado medio -> palabra clave o acción específica

------------------------------------------------------------
7) Manifestación material
Pieza posible:
“Esta estrategia no funciona porque el político sea carismático.
Funciona porque reorganiza el campo interpretativo antes de que el rival responda.
Si quieres que te mande un prompt para analizar cualquier maniobra pública con
esta estructura, escríbeme ‘estrategia’.”

------------------------------------------------------------
8) Evidencia / validación
Se valida si:
- llegan mensajes con la palabra clave,
- el público correcto se auto-selecciona,
- la transición a conversación privada es natural,
- la pieza no rompe la identidad del sistema.

Falla si:
- el CTA parece injerto externo,
- nadie entiende qué valor hay detrás,
- o el filtro atrae curiosidad vacía sin compatibilidad real.

EJEMPLO GUÍA 3
MONETIZACIÓN POR CURSO DE ESTRATEGIAS
================================================================================

1) Fuente estructural
Nombre:
Fuente de monetización por cursos de estrategias transferibles

Identidad:
Sistema que usa contenido público como mecanismo de captación y clasificación,
y usa un curso como puente entre atención y dinero.

La fuente no es:
- el curso aislado,
- el contenido aislado,
- ni una sola industria.

La fuente es:
una arquitectura que transforma lectura pública de casos en interés profundo
y luego en acceso pagado a una estructura replicable.

------------------------------------------------------------
2) Invariantes
- Debe existir una capa pública de atracción.
- Debe existir una capa profunda de estructuración.
- El valor monetizable debe ser un mecanismo transferible, no solo información.
- Debe existir continuidad entre contenido público y producto pagado.
- La monetización no puede romper la identidad cognitiva del sistema.

------------------------------------------------------------
3) Dimensiones intensionales
d1 = dominio temático
d2 = transferibilidad del mecanismo
d3 = profundidad del producto
d4 = credibilidad de la fuente
d5 = presión transaccional
d6 = claridad del puente entre pieza y curso
d7 = densidad de casos ejemplares
d8 = grado de institucionalidad del valor ofrecido

------------------------------------------------------------
4) Vector de instanciación
V3 = (
  dominio_tematico = estrategia_politica,
  transferibilidad = alta,
  profundidad_del_producto = alta,
  credibilidad = media-alta,
  presion_transaccional = media,
  claridad_del_puente = alta,
  densidad_de_casos = alta,
  institucionalidad_del_valor = alta
)

------------------------------------------------------------
5) Región de salida dominante
Región dominante:
Monetización por formación estratégica

Lectura:
La configuración ya no apunta solo a conversación privada.
Apunta a un producto estructurado que el receptor percibe como ampliación
metodológica seria.

------------------------------------------------------------
6) Adaptador
Adaptador:
Secuencia de contenido público + landing conceptual + oferta de curso

Lo que traduce:
- casos públicos -> demostración de competencia
- transferibilidad -> promesa de uso en otros contextos
- profundidad alta -> curso o programa
- institucionalidad alta -> percepción de valor serio

------------------------------------------------------------
7) Manifestación material
Secuencia posible:
Pieza 1:
“Cómo una maniobra pública cambió la lectura del electorado.”

Pieza 2:
“Esto no fue improvisación: fue reposicionamiento estructural.”

Pieza 3:
“Este patrón aparece en más campañas de las que parece.”

Puente:
“Si te interesa aprender a detectar, analizar y replicar este tipo de
estructuras en cualquier caso público, abrí un curso de estrategia aplicada.”

------------------------------------------------------------
8) Evidencia / validación
Se valida si:
- el curso se percibe como continuación natural del sistema,
- el contenido público alimenta el deseo de procedimiento,
- el alumno entiende que compra estructura y no solo información,
- existe conversión económica sin pérdida de identidad.

Falla si:
- el curso parece desconectado del contenido,
- la monetización destruye legitimidad,
- o el producto promete más de lo que el núcleo realmente sostiene.

EJEMPLO GUÍA 4
ARTEFACTO DE CÓDIGO COMO NODO DE REALIDAD
================================================================================

1) Fuente estructural
Nombre:
Fuente de automatización cognitiva mediada por artefactos

Identidad:
Sistema cuya unidad profunda no es el archivo de código individual, sino la
capacidad de traducir una arquitectura lógica a texto portable para que una IA
la comprenda, intervenga y devuelva modificaciones coherentes.

Aquí la fuente opera como:
- núcleo cognitivo proyectable,
- traductor entre arquitectura y lenguaje,
- puente entre cognición y ejecución material.

------------------------------------------------------------
2) Invariantes
- Debe existir una arquitectura lógica legible.
- Debe existir una proyección textual portable.
- Debe preservarse la relación entre estructura y modificación.
- El sistema debe permitir comprensión global, no solo fragmentaria.
- La salida debe ser materializable o accionable.

------------------------------------------------------------
3) Dimensiones intensionales
d1 = completitud del snapshot
d2 = granularidad del artefacto
d3 = capacidad de reconstrucción del sistema
d4 = precisión del objetivo de modificación
d5 = compatibilidad con materialización
d6 = trazabilidad del cambio
d7 = grado de autonomía cognitiva asistida

------------------------------------------------------------
4) Vector de instanciación
V4 = (
  completitud = alta,
  granularidad = media,
  reconstruccion_global = alta,
  objetivo_de_modificacion = preciso,
  compatibilidad_material = alta,
  trazabilidad = alta,
  autonomia_asistida = media-alta
)

------------------------------------------------------------
5) Región de salida dominante
Región dominante:
Intervención cognitiva sobre arquitectura lógica

Lectura:
La salida no es “contenido para audiencia”, sino modificación coherente del
sistema proyectado como texto.

------------------------------------------------------------
6) Adaptador
Adaptador:
Compilador cognitivo basado en artefacto

Traducción:
- snapshot textual -> mapa mental del repo
- objetivo -> diseño de cambio
- diseño -> patch artifact
- patch -> modificación materializable

------------------------------------------------------------
7) Manifestación material
Salida posible:
- patch JSONL,
- notas de integración,
- archivos nuevos,
- versiones actualizadas de módulos.

------------------------------------------------------------
8) Evidencia / validación
Se valida si:
- la IA comprende entrypoints, estructura y contratos,
- el patch respeta arquitectura y estilo,
- el cambio puede materializarse,
- la arquitectura resultante conserva coherencia.

Falla si:
- el artefacto es incompleto al punto de impedir cognición global,
- la salida rompe contratos estructurales,
- o la modificación no puede integrarse al repo real.

EJEMPLO GUÍA 5
CAMPO INTERPRETATIVO COMO FUENTE DE RESPUESTA REGULADA
================================================================================

1) Fuente estructural
Nombre:
Campo interpretativo institucional

Identidad:
Entidad que no produce piezas para un sujeto, sino que recibe entradas desde
agentes, las pondera con criterios internos y produce una salida regulada.

Este ejemplo es importante porque muestra que el modelo no se limita a creación
de contenido.
También puede modelar estructuras evaluadoras.

------------------------------------------------------------
2) Invariantes
- Debe existir una frontera de entrada.
- Debe existir una lógica interna de ponderación.
- Debe existir una salida diferencial.
- La fuente no puede confundirse con las entradas que recibe.
- Debe poder observarse una consecuencia.

------------------------------------------------------------
3) Dimensiones intensionales
d1 = tipo de entrada
d2 = prioridad institucional
d3 = severidad del criterio
d4 = umbral de aceptación
d5 = tolerancia al riesgo
d6 = velocidad de respuesta
d7 = memoria del sistema

------------------------------------------------------------
4) Vector de instanciación
V5 = (
  tipo_de_entrada = solicitud_publica,
  prioridad_institucional = alta,
  severidad = media-alta,
  umbral_de_aceptacion = alto,
  tolerancia_al_riesgo = baja,
  velocidad_de_respuesta = media,
  memoria_del_sistema = acumulativa
)

------------------------------------------------------------
5) Región de salida dominante
Región dominante:
Evaluación restrictiva con respuesta selectiva

------------------------------------------------------------
6) Adaptador
Adaptador:
Protocolo institucional de admisión / rechazo

------------------------------------------------------------
7) Manifestación material
Salida posible:
- aprobación,
- rechazo,
- derivación,
- clasificación de riesgo,
- ajuste de condiciones de ingreso.

------------------------------------------------------------
8) Evidencia / validación
Se valida si:
- dos entradas distintas reciben salidas distintas por razones recuperables,
- la fuente mantiene identidad evaluadora,
- la salida depende de criterios y no de arbitrariedad narrativa.

Falla si:
- ya no puede distinguirse entre campo y actor,
- no existe criterio observable,
- o no se produce ninguna consecuencia estructurada.

EJEMPLO GUÍA 6
ACONDICIONAMIENTO FÍSICO COMO FUENTE ONTOLÓGICA DE TRANSFORMACIONES
================================================================================

1) Fuente estructural
Nombre:
Modelo ontológico de acondicionamiento físico

Identidad:
Sistema que define dimensiones relevantes del cuerpo en un dominio particular
y permite construir transformaciones distintas según objetivo y contexto.

Este ejemplo es muy importante porque muestra con claridad que:
- la fuente no es la rutina concreta,
- la fuente no es el ejercicio aislado,
- la fuente es la ontología desde la cual pueden derivarse múltiples
  transformaciones particulares.

------------------------------------------------------------
2) Invariantes
- Deben existir variables o dimensiones del dominio.
- Debe existir estado inicial y estado objetivo.
- Debe existir una transformación definida sobre esas dimensiones.
- La adaptación debe depender del contexto del sujeto.
- La ejecución concreta debe heredar de una estructura previa.

------------------------------------------------------------
3) Dimensiones intensionales
d1 = objetivo principal
d2 = capacidades relevantes
d3 = limitaciones físicas
d4 = tiempo disponible
d5 = experiencia previa
d6 = lugar de entrenamiento
d7 = plazo propuesto
d8 = tolerancia de carga

------------------------------------------------------------
4) Vector de instanciación
V6 = (
  objetivo = bajar_de_peso,
  capacidades_relevantes = cardiorrespiracion + movilidad + tolerancia_de_carga,
  limitaciones_fisicas = lesion_en_rodilla,
  tiempo_disponible = 1h_dia,
  experiencia_previa = baja,
  lugar = casa,
  plazo = 9_meses,
  tolerancia_de_carga = media-baja
)

------------------------------------------------------------
5) Región de salida dominante
Región dominante:
Transformación progresiva con restricción articular

------------------------------------------------------------
6) Adaptador
Adaptador:
Diseñador de sesión particular de entrenamiento

Traducción:
- ontología general -> plan específico
- contexto del sujeto -> selección de módulos
- restricciones -> exclusión de ejercicios incompatibles
- objetivo -> priorización de variables

------------------------------------------------------------
7) Manifestación material
Salida posible:
- sesión particular,
- secuencia semanal,
- plan mensual,
- progresión por etapas.

------------------------------------------------------------
8) Evidencia / validación
Se valida si:
- la rutina responde al objetivo y al contexto,
- los módulos concretos son coherentes con la ontología,
- la salida conserva identidad con la fuente general,
- y la transformación puede observarse en las variables relevantes.

Falla si:
- la sesión parece arbitraria,
- el contexto no modifica la transformación,
- o la ejecución rompe restricciones esenciales.

CIERRE GENERAL
================================================================================

Los seis ejemplos muestran una misma tesis:

La pieza visible no debe tratarse como origen.
Debe tratarse como manifestación terminal de una configuración interna que
proviene de una fuente estructural.

Eso vale para:
- contenido digital,
- monetización,
- artefactos de código,
- campos interpretativos,
- ontologías de transformación,
- y otros dominios compatibles.

Dicho de forma sintética:

Fuente
-> dimensiones
-> vector
-> región de salida
-> adaptador
-> manifestación
-> evidencia

Cuando esta cadena puede reconstruirse,
el modelo ya no es solo explicativo;
se vuelve operable.
