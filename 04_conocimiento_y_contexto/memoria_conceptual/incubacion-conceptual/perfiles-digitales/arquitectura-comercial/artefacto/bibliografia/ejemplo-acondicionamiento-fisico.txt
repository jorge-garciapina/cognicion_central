Introducción
Antes de comenzar es necesario hacer algunas consideraciones:

1) Existen sistemas:
     + Tangibles -> construidos con materiales físicos, los cuales pueden ser percibidos con los sentidos.
     + Intangibles -> construidos con cognición pura, no es posible percibirlos con los sentidos.
   En ambos casos se busca lo mismo: efectuar una conversión o transformación, es decir, recibir una materia prima y
   convertirla en otra cosa.

2) Un sistema se compone de muchas partes que pueden ser llamados “subsistemas”, cada una con un fin dentro de la totalidad,
   no son independientes, son interdependientes.

3) Todos los sistemas evolucionan de lo simple a lo complejo (trayectoria de existencia).

El sistema que crearé es mixto (parte tangible / parte intangible), sus estructuras internas serán procesos; su fin global: la creación de la realidad.


Planteamiento fundamental
Cualquier transformación necesita estructura, no es opcional, es una ley, la cual puede resumirse en:
“nada viene de la nada”.

Para transformar se necesitan sistemas (los proveedores de la estructura) con entrada, salida y procesos internos claramente definidos.
En los sistemas tangibles es fácil comprender las responsabilidades de cada una de las partes:
  - En un reloj de cuerda se sabe que cada sistema tiene un fin.
  - En un automóvil se sabe que motor y ajuste de altura del asiento son “independientes” pero relacionados.

En los sistemas intangibles la comprensión no es tan inmediata, y la razón es que para entenderlos es necesario comprender razonamientos
más que movimientos.

----------------------
Inicio paréntesis 1
Sistemas cognitivos:
Hay una categoría aún más compleja, puesto que en los sistemas cognitivos es necesario comprender procesos meta-cognitivos, por ejemplo.
En un sistema intangible:
  - El razonamiento X es necesario para hacer Y.
En un sistema cognitivo:
  - Las estructuras A, B, C, ... son las causas del razonamiento.

En general, podríamos decir que se busca pasar de un [Estado inicial] a un [Estado final], donde cada estado se define como:

Estado:
  e1 = a1
  e2 = a2
   :
  ei = ai
   :
  en = an

Es importante aclarar:
- ei -> Variable de estado (en el ejemplo actual: fuerza, flexibilidad, resistencia, etc.). BAJO LA TEORÍA DE LAZO, ESTO ES CONOCIDO COMO "DIMENSIÓN ONTOLÓGICA"
- ai -> Valor de una variable de estado (es importante considerar que el [modelo] debe proporcionar formas de medir cada uno de estos valores, no es opcional).
  En el ejemplo actual:
  - Peso -> Kilogramos
  - Reflejos -> Tiempo de respuesta
  - Resistencia -> Duración máxima de un ejercicio (quizás)
  - ...

Es posible descubrir que [cambiar un estado] requiere llevar a cabo transformaciones en las [variables de estado]; los criterios de éxito están dados por los
valores de dichas variables.
EN EL PASO 3 SE ACLARA QUE EL ÉXITO O FRACASO DEPENDE DEL [Objetivo] FIJADO.


Paso 2
LO QUE SE ENTIENDE AQUÍ COMO [modelo del dominio] ES LA ONTOLOGÍA, LO QUE SE PROPUSO EN EL PASO 1 SUPONE (CASI DE FORMA ACCIDENTAL) LA EXISTENCIA DE UNA ONTOLOGÍA
Una vez que se tiene el [modelo del dominio], es necesario conocer el estado inicial y “proponer” un estado final, es decir:

Estado inicial:
  e1 = a1^i
  e2 = a2^i
   :
  en = an^i

            Transformación  ->

Estado final:
  e1 = a1^f
  e2 = a2^f
   :
  en = an^f


------------------------------------------------------------

La transformación puede ser representada como:

T([estado inicial]) = [estado final]

Para que cada uno de los valores de las variables de estado sea transformado, es necesario que:

T(e1, e2, ..., en) = { t1(e1), t2(e2), ..., tn(en) }   (estado final)

Es decir, la transformación debe tener la capacidad de operar en cada una de las variables de estado.
ESTO MUESTRA QUE LA ONTOLOGÍA SIRVE COMO "DOMINIO MATEMÁTICO" (PARA NO CONFUNDIR CON EL dominio: [acondicionamiento físico]) A LA TRANSFORMACIÓN, ES DECIR,
OPERARÁ SÓLO EN LAS DIMENSIONES ONTOLÓGICAS DEFINIDAS AL INICIO DEL PROCESO.

Paso 5
Una vez que se han definido las unidades mínimas de construcción, es importante entender cómo serán utilizadas; para esto es útil analizar una sesión de entrenamiento.

Creación de módulos
En esta sección "módulo" se entiende como:
“Arreglo de unidades mínimas (módulos simples) o de otros módulos (módulos compuestos) interconectados siguiendo reglas específicas”.

Siguiendo esta definición, podemos dar algunos ejemplos de módulos:

Ejemplo 5. Módulo simple: Serie de sentadillas
- Núcleo: sucesión ininterrumpida de sentadillas (repeticiones / iteraciones)
- Invariantes: solo puede haber sentadillas
- Dominio de variación:
  - velocidad
  - número de repeticiones / tiempo


Ejemplo 6. Módulo simple: Serie de abdominales
- Núcleo: sucesión ininterrumpida de abdominales
- Invariantes: solo abdominales
- Dominio de variación:
  - velocidad
  - repeticiones / tiempo


Ejemplo 7. Módulo simple: Sesión de caminadora
- Núcleo: intervalo de tiempo en caminadora
- Invariantes: lapso de tiempo ininterrumpido
- Dominio de variación:
  - cantidad de tiempo

Los 3 módulos anteriores son “simples”, es decir, se componen de unidades mínimas de dominio.
En el siguiente ejemplo se muestra un módulo “compuesto”.


Ejemplo 8. Módulo compuesto: Sesión de entrenamiento
- Núcleo: intervalo de tiempo en el que se ejecutarán diversos módulos (simples o compuestos)
- Invariantes:
  - se debe ejecutar al menos un módulo
- Dominio de variación:
  - variable de estado objetivo (EN SESIÓN)
  - grupos musculares
  - duración
  - número de módulos ( >= 1)
  - lugar (ubicación)
  - intensidad

La razón por la que una sesión de entrenamiento es un módulo compuesto es que consta de módulos simples.
Una sesión de entrenamiento se ve como algo parecido a:

Ejecución: Sesión de entrenamiento
- Sección 1: calentamiento
- Sección 2: lubricación
- Sección 3: 3 x (módulo simple(ms)1 + ms2 + ms3)
- Sección 4: 3 x (ms4 + ms5 + ms6)
- Sección 5: enfriamiento
- Sección 6: estiramiento

Si bien hay muchas variantes, el ejemplo anterior captura la esencia.

El [módulo de ejecución] puede ser compuesto:
- Sesión de entrenamiento

2) Debido a que la sesión de entrenamiento es en sí misma un [módulo de ejecución], entonces las sesiones de entrenamiento pueden ser utilizadas

Paso 6
En el paso anterior se explica cómo crear [módulos de ejecución], sin embargo no se menciona nada acerca de la relación que éstos tienen con la
transformación que se trata de entender. En este paso se explora la relación entre la ejecución y el diseño. (EJE DE EJECUCIÓN Y EJE ONTOLÓGICO)

Con respecto a las secciones (número de secciones, contenido de cada sección) se dijo que:
“... dependerá del objetivo (núcleo) fijado para esa sesión”. (ES DECIR, EL CONTENIDO DE CADA MODULO DE EJECUCIÓN DEPENDE DE LA ONTOLOGÍA)

Lo que esto significa es que cada sesión es una entidad con identidad propia, es decir, tiene un núcleo, invariantes y dominio de variación.
En general, es posible decir:

“Un módulo (simple, compuesto, de ejecución, ONTOLÓIGICO) es una entidad con identidad propia, la cual está dada/definida/creada por los parámetros estructurales:
- Núcleo
- Invariantes
- Dominio de variación”.

En la página 10 de este estudio ya se habla sobre este modelo aplicado a sesión de entrenamiento (ver Ejemplo 8), pero ahí se modela el
