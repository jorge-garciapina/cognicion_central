# Modelo Especializado del Módulo 12: `analizador_argumentativo`

## MAANC-12 · Analizador Argumentativo para Arquitectura Macro Narrativo-Cognitiva

**Sistema superior:** MAANC — Modelo de Arquitectura Macro Narrativo-Cognitiva  
**Arquitectura de integración:** ACCD / TMC  
**Módulo:** 12. `analizador_argumentativo`  
**Tipo:** estructura cognitiva de análisis, reconstrucción y validación argumentativa  
**Función principal:** reconstruir cómo una manifestación defiende, justifica, matiza, refuta o transforma una posición dentro de su arquitectura macro.

---

# 1. Definición especializada

El `analizador_argumentativo` es el módulo del MAANC encargado de reconstruir la **arquitectura de justificación** de una manifestación. Su tarea no es solamente detectar “argumentos” en sentido escolar, sino identificar cómo una manifestación usa tesis, evidencias, garantías, objeciones, matices, inferencias, autoridades, ejemplos, analogías y consecuencias para transformar el estado interpretativo del receptor.

Definición operativa:

```txt
analizador_argumentativo =
  módulo que detecta y organiza las unidades de defensa, soporte,
  inferencia, objeción y matización de una manifestación,
  explicando cómo esas unidades hacen avanzar la arquitectura macro.
```

Definición en lenguaje ACCD:

```txt
analizador_argumentativo =
  estructura cognitiva que convierte la argumentación dispersa de un texto
  en un grafo de responsabilidades justificativas, conectado con la evolución
  narrativo-cognitiva de la manifestación.
```

La pregunta central no es solo:

```txt
¿Qué argumento aparece aquí?
```

sino:

```txt
¿Qué responsabilidad cumple este movimiento argumentativo dentro de la arquitectura macro?
```

Por eso, el módulo debe reconstruir simultáneamente tres capas:

```txt
1. capa argumentativa:
   qué se afirma, qué lo sostiene, qué lo limita, qué lo objeta.

2. capa inferencial:
   qué puentes lógicos o prácticos permiten pasar de soporte a tesis.

3. capa narrativo-cognitiva:
   cómo ese movimiento transforma el estado interpretativo del receptor.
```

# 2. Problema que resuelve el módulo

En muchos análisis, la argumentación se reduce a una lista de ideas:

```txt
- el autor dice X
- luego da un ejemplo
- luego concluye Y
```

Ese nivel es insuficiente. El `analizador_argumentativo` debe detectar la maquinaria interna:

```txt
- X funciona como claim central.
- El ejemplo no es simplemente ilustración: opera como ground.
- El salto de ejemplo a conclusión requiere un warrant implícito.
- La conclusión está cualificada, no es absoluta.
- Hay una objeción anticipada que limita el alcance.
- Todo esto produce una transformación cognitiva específica.
```

El módulo resuelve cinco problemas:

```txt
1. evita confundir tema con tesis;
2. evita confundir ejemplo con prueba;
3. hace visibles los warrants implícitos;
4. detecta matices, objeciones y condiciones de excepción;
5. conecta los argumentos con la arquitectura macro del texto.
```

# 3. Fuentes teóricas integradas

El módulo toma elementos de varias tradiciones, pero cada tradición cumple una tarea específica.

## 3.1. Toulmin

El modelo de Stephen Toulmin aporta la estructura base:

```txt
claim       → afirmación defendida
grounds     → soporte o datos
warrant     → regla que conecta grounds con claim
backing     → respaldo del warrant
qualifier   → grado de fuerza o alcance
rebuttal    → excepción, objeción o condición de falla
```

Toulmin sirve para reconstruir la anatomía mínima de una unidad argumentativa.

## 3.2. Pragma-dialéctica

Aporta la idea de que la argumentación ocurre dentro de una diferencia de opinión. Permite distinguir fases como:

```txt
confrontación
apertura
argumentación
conclusión
```

Dentro del módulo, esto ayuda a detectar si un tramo abre una disputa, fija presupuestos, defiende una posición o cierra una controversia.

## 3.3. Walton, Reed y Macagno

Aportan la teoría de esquemas argumentativos:

```txt
argumento por ejemplo
argumento por analogía
argumento causal
argumento por autoridad
argumento pragmático
argumento por consecuencias
argumento por signo
argumento abductivo
argumento por clasificación
argumento por definición
```

Esto permite detectar qué tipo de inferencia está usando el texto.

## 3.4. Critical questions

Cada esquema argumentativo debe evaluarse mediante preguntas críticas. Por ejemplo, un argumento por autoridad exige preguntar si la fuente es competente, pertinente y no contradicha por otras fuentes. Un argumento por analogía exige preguntar si la semejanza es estructuralmente relevante o superficial.

## 3.5. RST y relaciones retóricas

La Rhetorical Structure Theory complementa el módulo porque muchas unidades argumentativas aparecen como relaciones retóricas:

```txt
evidencia
justificación
concesión
contraste
elaboración
preparación
motivación
resultado
condición
```

## 3.6. ACCD / TMC

La ACCD aporta la integración superior: cada movimiento argumentativo no debe quedarse como componente lógico aislado, sino integrarse dentro de:

```txt
arquitectura_macro
familias cognitivas
responsabilidades narrativas
mNodes
conexiones
grafo argumentativo
transformación del receptor
```

```txt

  → identifica qué foco atencional sostiene cada argumento.

integrador_ACCD
  → convierte todo en arquitectura macro compatible con el sistema.
```

# 5. Unidad mínima del módulo

La unidad mínima no es la oración. La unidad mínima es el **movimiento argumentativo**.

```txt
movimiento_argumentativo =
  unidad textual que cumple una función dentro de la defensa, soporte,
  matización, refutación o evaluación de una posición.
```

Un movimiento argumentativo puede ocupar:

```txt
una frase,
un párrafo,
una anécdota,
una cita,
una sección,
una mini-historia,
un ejemplo,
una analogía,
un caso histórico,
un experimento,
una pregunta retórica.
```

Por eso, el módulo debe mirar la función, no solo la forma superficial.

Ejemplo:

```txt
Una historia puede funcionar como:
  - ground ejemplificativo,
  - analogía,
  - evidencia emocional,
  - contraejemplo,
  - preparación del claim,
  - backing de un principio,
  - activador de identificación.
```

# 7. Componentes internos del módulo


No toda afirmación es claim. Una afirmación se vuelve claim cuando el texto la usa como posición defendible o cuando requiere soporte para ser aceptada.

# 8. Taxonomía de claims

## 8.1. Claim descriptivo

Afirma que algo es el caso.

```txt
La crítica produce resentimiento.
```

## 8.2. Claim causal

Afirma que una cosa produce otra.

```txt
La crítica pone a la persona en actitud defensiva.
```

## 8.3. Claim normativo

Afirma que algo debe hacerse o evitarse.

```txt
No debemos criticar, condenar ni quejarnos.
```

## 8.4. Claim definicional

Afirma cómo debe entenderse un concepto.

```txt
La crítica es una forma de agresión al sentido de importancia.
```

## 8.5. Claim clasificatorio

Afirma que algo pertenece a una categoría.

```txt
Este caso es un ejemplo de autojustificación.
```

## 8.6. Claim evaluativo

Afirma que algo es útil, inútil, peligroso, admirable, defectuoso.

```txt
La crítica es inútil y peligrosa.
```

## 8.7. Claim metodológico

Afirma que un procedimiento es adecuado.

```txt
Es más eficaz empezar por uno mismo que intentar corregir a otros.
```

## 8.8. Claim interpretativo

Afirma cómo debe interpretarse un fenómeno.

```txt
La reacción de la persona criticada debe interpretarse como defensa de su orgullo.
```

## 8.9. Claim pragmático

Afirma qué acción conviene por sus consecuencias.

```txt
Comprender a los demás produce mejores resultados que criticarlos.
```

# 9. Taxonomía de grounds

## 9.1. Ground empírico

Datos, observaciones, experimentos o hechos verificables.

## 9.2. Ground ejemplificativo

Un caso concreto que ilustra o apoya una tesis.

## 9.3. Ground narrativo

Una historia usada como soporte.

## 9.4. Ground testimonial

Declaración de una persona o autoridad.

## 9.5. Ground conceptual

Definición, distinción o principio.

## 9.6. Ground histórico

Acontecimiento histórico usado como evidencia.

## 9.7. Ground psicológico

Principio sobre conducta, motivación, emoción o cognición.

## 9.8. Ground pragmático

Consecuencias prácticas de una acción.

## 9.9. Ground analógico

Relación con otro dominio estructuralmente semejante.

## 9.10. Ground textual

Evidencia tomada del propio texto analizado.

# 10. Taxonomía de warrants

## 10.1. Warrant causal

Si X produce Y, entonces la presencia de X explica Y.

## 10.2. Warrant pragmático

Si una acción produce mejores consecuencias, debe preferirse.

## 10.3. Warrant psicológico

Si una acción afecta orgullo, defensa o resentimiento, probablemente modificará la conducta del receptor.

## 10.4. Warrant ético

Si una acción trata injustamente a otro, debe evitarse.

## 10.5. Warrant analógico

Si dos casos comparten estructura relevante, lo aprendido en uno puede transferirse al otro.

## 10.6. Warrant por autoridad

Si una autoridad pertinente sostiene X, X gana aceptabilidad provisional.

## 10.7. Warrant por generalización

Si muchos casos muestran un patrón, puede formularse una regularidad.

## 10.8. Warrant definicional

Si algo cumple los criterios de una definición, pertenece a esa categoría.

## 10.9. Warrant abductivo

Si una hipótesis explica mejor los datos disponibles, puede aceptarse provisionalmente.

## 10.10. Warrant de modelaje ejemplar

Si una figura ejemplar actúa de cierta manera y su resultado es admirable, esa conducta puede presentarse como modelo.

# 11. Taxonomía de qualifiers

Los qualifiers regulan la fuerza de un claim.

```txt
certeza:
  necesariamente, probablemente, posiblemente.

frecuencia:
  siempre, a menudo, casi siempre, algunas veces.

alcance:
  en este contexto, bajo estas condiciones, para este tipo de casos.

intensidad:
  fuertemente, moderadamente, débilmente.

provisionalidad:
  provisionalmente, hasta nueva evidencia, en principio.

generalidad:
  en general, no en todos los casos, típicamente.
```

El módulo debe registrar qualifiers porque muchas tesis importantes están matizadas. Ignorar el matiz distorsiona el argumento.

# 12. Taxonomía de rebuttals

## 12.1. Excepción

Caso donde la tesis no aplica.

## 12.2. Objeción directa

Razón contra la tesis.

## 12.3. Contraejemplo

Caso que contradice una generalización.

## 12.4. Limitación metodológica

Restricción sobre la evidencia o el método.

## 12.5. Matización

Aclaración que reduce el alcance.

## 12.6. Concesión

Aceptación parcial de un punto contrario.

## 12.7. Respuesta a objeción

Defensa frente a una crítica anticipada.

## 12.8. Desplazamiento

La objeción no se responde directamente, sino que se cambia el marco interpretativo.

# 13. Esquemas argumentativos

El módulo debe reconocer esquemas argumentativos. Cada esquema cumple una función distinta.

## 13.1. Argumento por ejemplo

Usa un caso concreto para apoyar una generalización o principio.

Preguntas críticas:

```txt
¿El ejemplo es representativo?
¿Hay contraejemplos relevantes?
¿El ejemplo prueba o solo ilustra?
```

## 13.2. Argumento por acumulación de ejemplos

Usa varios casos para crear una regularidad.

Preguntas críticas:

```txt
¿Los casos son suficientemente diversos?
¿Comparten el mismo patrón causal?
¿Hay selección sesgada de casos?
```

## 13.3. Argumento por autoridad

Usa la palabra de una figura o experto.

Preguntas críticas:

```txt
¿La autoridad es pertinente?
¿Habla dentro de su dominio?
¿Hay autoridades contrarias?
```

## 13.4. Argumento causal

Afirma que X produce Y.

Preguntas críticas:

```txt
¿Hay evidencia de causalidad?
¿Puede haber otra causa?
¿Se confunde correlación con causalidad?
```

## 13.5. Argumento pragmático

Defiende una acción por sus consecuencias.

Preguntas críticas:

```txt
¿Las consecuencias son probables?
¿Son deseables?
¿Hay costos ocultos?
```

## 13.6. Argumento por analogía

Transfiere comprensión de un dominio a otro.

Preguntas críticas:

```txt
¿La semejanza es estructural o superficial?
¿Las diferencias invalidan la transferencia?
¿La analogía prueba, sugiere o ilustra?
```

## 13.7. Argumento por modelo ejemplar

Presenta una figura admirable como modelo de conducta.

Preguntas críticas:

```txt
¿El modelo es pertinente?
¿La conducta ejemplar es transferible?
¿Se omiten condiciones contextuales?
```

## 13.8. Argumento emocional-controlado

Usa una escena emotiva para volver sensible una tesis.

Preguntas críticas:

```txt
¿La emoción clarifica o manipula?
¿La escena representa el problema general?
¿La conclusión depende demasiado del pathos?
```

## 13.9. Argumento por contraste

Muestra dos modos de actuar o pensar para favorecer uno.

Preguntas críticas:

```txt
¿El contraste es justo?
¿Ambas posiciones están representadas correctamente?
¿Hay posiciones intermedias?
```

## 13.10. Argumento abductivo

Propone la mejor explicación disponible.

Preguntas críticas:

```txt
¿Explica más datos que las alternativas?
¿Hay hipótesis rivales?
¿La explicación es demasiado amplia?
```

# 14. Movimientos argumentativos dentro de arquitectura macro

Un argumento puede desempeñar distintos papeles en la trayectoria global.

## 14.1. Apertura argumentativa

Instala una diferencia de opinión o una tesis problemática.

## 14.2. Desestabilización de creencia común

Ataca una intuición inicial del receptor.

## 14.3. Fundamentación

Aporta soportes para hacer aceptable una tesis.

## 14.4. Generalización

Pasa de casos a principio.

## 14.5. Reencuadre

Cambia el modo en que el receptor interpreta el problema.

## 14.6. Refutación

Desactiva una posición rival.

## 14.7. Concesión

Acepta parcialmente una objeción para ganar precisión.

## 14.8. Matización

Reduce el alcance del claim para volverlo más fuerte.

## 14.9. Modelo ejemplar

Presenta una conducta como patrón a imitar.

## 14.10. Cierre argumentativo

Estabiliza la conclusión.

## 14.11. Apertura proyectiva

Deja una consecuencia o pregunta para otro tramo.

# 15. Arquitecturas argumentativas frecuentes

## 15.1. Tesis → soporte → cierre

```txt
claim → grounds → conclusion
```

## 15.2. Problema → tesis → justificación

```txt
problema → posición → razones
```

## 15.3. Tesis → objeción → respuesta

```txt
claim → objection → respuesta
```

## 15.4. Evidencia → inferencia → tesis

```txt
grounds → warrant → claim
```

## 15.5. Tesis rival → refutación → tesis propia

```txt
posición rival → refutación → tesis refinada
```

## 15.6. Concesión → distinción → tesis refinada

```txt
concesión → distinción → claim refinado
```

## 15.7. Caso → principio → aplicación

```txt
caso → principio → aplicación
```

## 15.8. Acumulación de casos → regularidad → prescripción

```txt
caso 1 → caso 2 → caso 3 → patrón → regla práctica
```

## 15.9. Error común → consecuencia negativa → alternativa superior

```txt
conducta común → daño → alternativa
```

## 15.10. Modelo negativo → modelo positivo → regla de conducta

```txt
ejemplo de error → ejemplo de virtud → principio práctico
```

# 16. Protocolo de análisis paso a paso

## Paso 1. Delimitar unidad de análisis

Determinar si se analiza:

```txt
texto completo
capítulo
sección
fragmento
transcripción
manifestación codominial
```

## Paso 2. Detectar presión argumentativa

Buscar zonas donde el texto intenta persuadir, defender, justificar, refutar o corregir.

Indicadores:

```txt
por eso
porque
ya que
sin embargo
pero
por consiguiente
esto demuestra
no significa que
entonces
si... entonces
```

## Paso 3. Extraer claims candidatos

Localizar afirmaciones defendibles.

## Paso 4. Clasificar claims

Determinar tipo, nivel y centralidad.

## Paso 5. Asociar grounds

Vincular cada claim con datos, ejemplos, casos, testimonios o principios.

## Paso 6. Inferir warrants

Reconstruir el puente lógico o práctico que conecta el soporte con la tesis.

## Paso 7. Detectar backing

Identificar autoridad, teoría, experiencia o principio que respalda el warrant.

## Paso 8. Detectar qualifiers

Registrar matices de frecuencia, certeza, alcance o condición.

## Paso 9. Detectar rebuttals

Registrar objeciones, excepciones, contraejemplos, concesiones y respuestas.

## Paso 10. Clasificar esquemas argumentativos

Identificar si el argumento opera por ejemplo, autoridad, analogía, causalidad, consecuencia, etc.

## Paso 11. Formular preguntas críticas

Evaluar vulnerabilidades del argumento.

## Paso 12. Construir mapa argumentativo

Crear nodos y aristas.

## Paso 13. Ubicar en arquitectura macro

Explicar qué papel cumple cada movimiento dentro de la evolución del texto.

## Paso 14. Diagnóstico final

Evaluar fuerza, cobertura, saltos inferenciales, objeciones no resueltas y transformación cognitiva.

# 18. Sistema de validación

## 18.1. Validación de claim

```txt
[ ] El claim está formulado claramente.
[ ] Se distingue de tema o descripción.
[ ] Se clasificó su tipo.
[ ] Se ubicó su nivel: global, macro, local.
[ ] Se identificó su función en la arquitectura macro.
```

## 18.2. Validación de soporte

```txt
[ ] Cada claim central tiene grounds.
[ ] Los grounds están clasificados.
[ ] Se distingue ilustración de evidencia.
[ ] Se evalúa representatividad.
```

## 18.3. Validación de warrant

```txt
[ ] Se reconstruyó el puente inferencial.
[ ] Se indicó si es explícito o inferido.
[ ] Se clasificó el tipo de warrant.
[ ] Se detectó vulnerabilidad.
```

## 18.4. Validación de matices

```txt
[ ] Se detectaron qualifiers.
[ ] Se respetó el alcance real de la tesis.
[ ] No se convirtió una tesis matizada en absoluta.
```

## 18.5. Validación de objeciones

```txt
[ ] Se detectaron rebuttals explícitos.
[ ] Se detectaron objeciones implícitas relevantes.
[ ] Se indicó si fueron respondidas, concedidas, desplazadas o dejadas abiertas.
```

## 18.6. Validación macro

```txt
[ ] Cada movimiento argumentativo está ubicado en la arquitectura macro.
[ ] Se explica la transformación cognitiva producida.
[ ] El mapa argumentativo no queda como lista plana.
```

# 20. Errores frecuentes

## Error 1. Confundir tema con tesis

Tema: “crítica”.  
Tesis: “la crítica es inútil y peligrosa porque provoca defensa y resentimiento”.

## Error 2. Confundir ejemplo con prueba

Un ejemplo puede ilustrar sin demostrar. El módulo debe decidir si el ejemplo opera como ground fuerte, ilustración, analogía o pathos.

## Error 3. No reconstruir warrants

Muchos textos dependen de puentes implícitos. Si no se reconstruyen, el argumento queda incompleto.

## Error 4. Ignorar qualifiers

Expresiones como “con frecuencia”, “casi siempre”, “probablemente” o “en muchos casos” regulan el alcance del claim.

## Error 5. Tratar toda objeción como refutación

Algunas objeciones son integradas, matizadas o usadas para reforzar la tesis.

## Error 6. Sacar el argumento de la arquitectura macro

Un argumento no solo prueba. También puede abrir tensión, intensificar una escena, preparar una conclusión, generar identificación o cerrar un recorrido.
