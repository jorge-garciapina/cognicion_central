TITLE: Artifact — Cognitive Photograph of a Logical Architecture (Self-Contained Definition)
VERSION: 1.1.0
STATUS: Concept Definition + Reusable Practical Template
AUDIENCE: Projects with zero prior knowledge about artifacts
PRIMARY GOAL: Enable Artificial Intelligence to “see” an entire logical architecture as a whole.

───────────────────────────────────────────────────────────────────────────────
1) CORE DEFINITION
───────────────────────────────────────────────────────────────────────────────
Definition:
An ARTIFACT is a cognitive photograph of a large logical architecture (for example, a code
project), encoded in a format readable by Artificial Intelligence, so that Artificial Intelligence
can perceive the whole system, infer its internal structure and rules, and convert that global
understanding into usable cognition.

Key consequence (crucial):
The artifact does not only produce outputs “usable by a human”.
It also allows a project with a logical architecture to gain a degree of cognition, because the
project can be paired with Artificial Intelligence that has access to the artifact and can act as
a cognitive layer for that architecture.

In short:
Artifact = “Cognitive Photograph of the Architecture” that grants “System-Level Cognition”
through Artificial Intelligence.

───────────────────────────────────────────────────────────────────────────────
2) WHY THIS CONCEPT EXISTS (THE PROBLEM IT SOLVES)
───────────────────────────────────────────────────────────────────────────────
A large system (a code project) is not merely “many files”.
It is a single architecture expressed through many components.

Humans:
- Can understand a single file at a time with high clarity.
- Struggle to perceive the entire architecture at once when the system becomes large.

Artificial Intelligence (when given enough text context):
- Can ingest large volumes of text and cross-reference them.
- Can infer global patterns: modules, conventions, contracts, constraints, style, and “how the
  system thinks”.

Therefore:
The artifact is the bridge that makes the whole architecture cognitively accessible to
Artificial Intelligence, which in turn can provide cognition back to:
(A) the human (explanations, maps, guided changes), and
(B) the project itself (a cognitive layer that can maintain coherence while evolving).

This is analogous to:
- A human uses a photograph to “see” a complex scene in a single view.
- Artificial Intelligence uses an artifact to “see” a complex architecture in a single ingestible object.

───────────────────────────────────────────────────────────────────────────────
3) WHAT “COGNITION” MEANS IN THIS CONTEXT
───────────────────────────────────────────────────────────────────────────────
“Cognition” here means the ability to perform high-level operations that require global
context, such as:

3.1 Cognition provided to the human
- Global explanation of architecture (“how the parts form a whole”).
- Identification of implicit conventions (naming, layering, module boundaries).
- Extraction of system rules (inputs/outputs, formats, restrictions, invariants).
- Actionable “radiography” of the project: what exists, why, how it connects, what risks exist.
- Guidance for modifications that match the project style.

3.2 Cognition provided to the project (through Artificial Intelligence)
When the project is paired with Artificial Intelligence that has the artifact, the project gains
capabilities that resemble cognition, for example:
- Self-description: the project can be “asked” to explain itself via Artificial Intelligence.
- Coherence-preserving evolution: generate new functionality that follows the architecture.
- Constraint awareness: avoid changes that break established patterns and restrictions.
- Architectural continuity: incorporate additions that remain consistent with existing structure.

Important:
This does not mean the project literally “thinks”.
It means the project gains a cognitive interface: Artificial Intelligence + artifact behaves like a
cognitive layer attached to the architecture.

───────────────────────────────────────────────────────────────────────────────
4) THE MINIMAL STRUCTURE OF AN ARTIFACT
───────────────────────────────────────────────────────────────────────────────
An artifact is composed of many “units”.
Each unit must have two essential parts:

(1) Address
A stable identifier that names the unit inside the architecture.

(2) Content
The raw content of that unit, readable by Artificial Intelligence.

This is the minimal idea:
Address + Content

Nothing else is required to define the concept.

───────────────────────────────────────────────────────────────────────────────
5) ADDRESS: WHAT IT IS AND WHY IT MATTERS
───────────────────────────────────────────────────────────────────────────────
Address is not “just a path”.
Address is the coordinate system of the architecture as represented in the artifact.

An Address must be:
- Stable: it does not change arbitrarily between artifact versions.
- Unique enough: it points to one intended unit.
- Meaningful: it reflects how units are organized in the architecture.

In the code artifact example:
- Address is typically a file path, such as:
  "src/server.ts"
  "src/features/auth/route.ts"
  "README.md"

In a graph-oriented representation of the same project:
- Address can identify nodes or edges explicitly, such as:
  "graph/node/auth-service"
  "graph/edge/auth-service->user-repo"
  "graph/edge/http-route:/api/login->auth-service"

This matters because:
- Address is what lets Artificial Intelligence relate units, detect structure, and build a global map.

───────────────────────────────────────────────────────────────────────────────
6) CONTENT: RAW MATERIAL FOR ARCHITECTURAL PERCEPTION
───────────────────────────────────────────────────────────────────────────────
Content is the raw, uncompressed logic of the architecture.

In the code artifact example:
- Content is source code and project text:
  - TypeScript, JavaScript, configuration files, documentation, schema definitions.

The key property:
- Content should be supplied “as-is” (raw), because the artifact is meant to be a cognitive
  photograph: Artificial Intelligence must see the real structure, not only a human-written summary.

Artificial Intelligence uses this raw material to infer:
- conventions,
- boundaries,
- module responsibilities,
- repeated patterns,
- internal constraints,
- style of programming,
- expected formats.

───────────────────────────────────────────────────────────────────────────────
7) A PRACTICAL ARTIFACT FORMAT (JSONL / NDJSON) 
───────────────────────────────────────────────────────────────────────────────
A common practical format is line-oriented text:
- One JSON object per line
- Each line = one unit (Address + Content)

Minimal line schema:
{
  "address": "string",
  "content": "string"
}

In the code artifact example, “address” can be “path”:
{
  "path": "src/server.ts",
  "content": "..."
}

Both are valid as long as the idea is preserved:
- stable Address
- readable Content

Why line-oriented?
- It scales to many units.
- It is easy to stream and to process.
- It supports “cognitive ingestion” as a single document.

───────────────────────────────────────────────────────────────────────────────
8) EXAMPLES (FOCUSED ON THE CODE ARTIFACT EXAMPLE)
───────────────────────────────────────────────────────────────────────────────
8.1 Example: Code artifact lines (file-based Address)
Line 1:
{
  "path": "package.json",
  "content": "{ \"name\": \"api\", \"dependencies\": { ... } }"
}

Line 2:
{
  "path": "src/main.ts",
  "content": "import { startServer } from './server';\nstartServer();"
}

Line 3:
{
  "path": "src/features/auth/route.ts",
  "content": "export function registerAuthRoutes(app) { ... }"
}

What Artificial Intelligence can infer from this:
- What the entry point is.
- How routing is organized (feature-based, layered, etc.).
- Naming conventions and code style.
- Where business logic likely lives.
- How modules connect through imports and function usage.

8.2 Example: Code artifact lines (graph-based Address for architecture)
Line 1:
{
  "address": "graph/node/auth-service",
  "content": "{ \"responsibility\": \"authenticate users\", \"inputs\": [\"credentials\"], \"outputs\": [\"token\"] }"
}

Line 2:
{
  "address": "graph/edge/http-route:/api/login->auth-service",
  "content": "{ \"method\": \"POST\", \"contract\": \"LoginRequest -> LoginResponse\" }"
}

This illustrates the same principle:
Address + Content can represent architecture directly, not only files.

───────────────────────────────────────────────────────────────────────────────
9) WHAT THE ARTIFACT ENABLES (CAPABILITIES)
───────────────────────────────────────────────────────────────────────────────
Given a code project artifact, Artificial Intelligence can typically provide:

9.1 Global understanding
- Architecture summary (modules, layers, major responsibilities).
- A “map” of how the project is structured and why.

9.2 Rule extraction
- Implicit formats: naming patterns, folder structure conventions.
- Implicit restrictions: “this module never imports that layer”, “this folder is purely utilities”.

9.3 Style inference
- The project’s programming style and repeated idioms.
- How errors are handled, how types are expressed, how configuration is shaped.

9.4 Coherent extension (new functionality)
This is central:
Artificial Intelligence can generate new functionality consistent with:
- existing architecture boundaries,
- naming conventions,
- internal formats,
- implicit constraints,
- style of code.

That coherence is the practical meaning of “the artifact makes change as easy as changing one file”:
the change is guided by global architecture, not by a local guess.

9.5 Iterative evolution
- You can regenerate an updated artifact after changes.
- Artificial Intelligence ingests the updated “photograph” and continues evolution consistently.

───────────────────────────────────────────────────────────────────────────────
10) THE STANDARD COGNITIVE LOOP (ARTIFACT-DRIVEN DEVELOPMENT)
───────────────────────────────────────────────────────────────────────────────
This is the simplest loop that expresses the concept:

Step 1: Capture
- Produce an artifact from the code project (Address + Content for all relevant units).

Step 2: Ingest
- Provide the artifact to Artificial Intelligence.

Step 3: Cognition
- Artificial Intelligence infers architecture, constraints, formats, and style.

Step 4: Action
- Request: explanation, architecture map, or new functionality consistent with the system.

Step 5: Update
- Apply the changes to the real project.
- Regenerate the artifact (new photograph).
- Repeat.

The artifact is what keeps global cognition stable across iterations.

───────────────────────────────────────────────────────────────────────────────
11) PRACTICAL NOTES FOR THE CODE ARTIFACT EXAMPLE (OPTIONAL BUT USEFUL)
───────────────────────────────────────────────────────────────────────────────
These notes are not part of the definition; they are practical recommendations when
the artifact is used for a code project.

11.1 Preserve architecture boundaries
- Keep paths stable where possible.
- Include enough structural files (entry points, routing modules, configuration).

11.2 Keep content readable as text
- Prefer plain text content for source/config/docs.
- If a unit is not text, store a placeholder or metadata rather than raw binary content.

11.3 Make the artifact “cognitively complete”
- Include files that define conventions and architecture (not only business logic):
  - configuration,
  - routing,
  - types or schemas,
  - documentation that explains assumptions.

Purpose of these notes:
Maximize Artificial Intelligence’s ability to infer global structure.

───────────────────────────────────────────────────────────────────────────────
12) ONE-SENTENCE DEFINITION (FOR FAST REUSE)
───────────────────────────────────────────────────────────────────────────────
An artifact is a cognitive photograph of a large logical architecture, represented as a set of
addressable units (Address + Content) readable by Artificial Intelligence, enabling Artificial
Intelligence to perceive the whole system, infer its rules and structure, and provide cognition
both to humans and to the project’s architecture itself through coherent understanding and evolution.
