# Estructura expandida del guion

## Eventos cognitivos, subeventos cognitivos y módulos MAANC asociados

**Tema del guion:** racionalización afectiva  
**Formato:** video ensayístico para YouTube  
**Arquitectura base:** reconocimiento, generalización, formalización, diseño deliberado y cierre operativo del juego de la influencia  
**Unidad macro:** evento cognitivo  
**Unidad interna:** subevento cognitivo

**Nota de actualización:** el nombre "racionalización afectiva" queda como rótulo interno de trabajo; el Evento Cognitivo 3 ya no lo presenta como término académico estabilizado, sino como modelo psicológico compuesto construido a partir de teorías existentes.

---

# 0. Propósito del documento

Este documento expande la **estructura del guion** en una arquitectura operativa compuesta por:

```txt
Evento Cognitivo
  → Subeventos Cognitivos
    → Módulos MAANC utilizados para construir cada subevento
```

La intención no es todavía escribir el guion final, sino crear una estructura suficientemente precisa para que después pueda desarrollarse cada parte del video sin improvisar.

Cada **evento cognitivo** cumple una función macro dentro de la transformación del espectador. Cada **subevento cognitivo** cumple una función local dentro del evento. Los módulos MAANC permiten justificar por qué ese subevento existe, qué operación realiza y cómo contribuye a la trayectoria completa.

La estructura general actualizada del guion es:

```txt
Evento Cognitivo 1 — Caso ancla de reconocimiento
  → hacer visible el mecanismo sin nombrarlo

Evento Cognitivo 2 — Generalización humana
  → convertir el caso inicial en patrón general

Evento Cognitivo 3 — Formalización psicológica basada en teorías existentes
  → construir un modelo psicológico respaldado por bibliografía

Evento Cognitivo 4 — Diseño deliberado del patrón
  → mostrar que el modelo de doble capa puede ser construido deliberadamente por entidades políticas o comerciales

Evento Cognitivo 5 — El juego de la influencia
  → cerrar el video convirtiendo el patrón en un modelo operativo de influencia con objetivo, recursos, condiciones de fracaso, intervención predecisional y regla terminal
```

**Nota estructural actualizada:** el guion termina en el Evento Cognitivo 5. Los antiguos Eventos Cognitivos 6, 7 y 8 quedan eliminados de esta arquitectura porque sus funciones terminales se condensan dentro del nuevo EC5: demostración operativa, retorno reflexivo y cierre memorable.

# 1. Regla estructural de construcción

Los subeventos no deben entenderse como “partes del video” en sentido superficial. No son simplemente:

```txt
introducción
contexto
ejemplo
cierre
```

Deben entenderse como **operaciones cognitivas internas**:

```txt
activar reconocimiento
mostrar contraste
crear disonancia
abstraer patrón
formalizar modelo
transferir dominio
interpelar al espectador
cristalizar regla
```

Por eso, la pregunta correcta para cada subevento es:

```txt
¿Qué operación cognitiva debe ocurrir aquí para que el evento cognitivo cumpla su función?
```

# 2. Módulos MAANC usados en la construcción

## 2.1. `segmentador_funcional`

Función principal en este documento:

```txt
Dividir cada evento cognitivo en subeventos según cambios de responsabilidad funcional.
```

No segmenta por duración, párrafo o escena. Segmenta por cambio de operación:

```txt
mostrar
contrastar
abstraer
nombrar
transferir
demostrar
interpelar
cerrar
```

## 2.2. `constructor_de_trayectoria_narrativa`

Función principal:

```txt
Ordenar los subeventos como una transformación progresiva del estado mental del espectador.
```

Pregunta guía:

```txt
¿Desde qué estado entra el espectador y hacia qué estado debe salir?
```

## 2.3. `modelador_de_situacion_cognitiva`

Función principal:

```txt
Definir qué actualización mental produce cada subevento.
```

Permite preguntar:

```txt
¿Qué entiende ahora el espectador que antes no entendía?
¿Qué sospecha queda instalada?
¿Qué distinción se vuelve disponible?
```

## 2.4. `detector_de_estructura_expositiva`

Función principal:

```txt
Organizar definiciones, contrastes, explicaciones, matrices y ejemplos.
```

Es especialmente útil cuando el guion debe explicar un concepto sin volverlo demasiado abstracto.

## 2.5. `analizador_de_moves_retoricos`

Función principal:

```txt
Convertir un subevento cognitivo en una acción discursiva concreta.
```

Ejemplos de moves:

```txt
preguntar
contrastar
interpelar
matizar
advertir
condensar
abrir sospecha
cerrar con regla
```

## 2.6. `analizador_intencional_atencional`

Función principal:

```txt
Determinar qué debe mirar mentalmente el espectador en cada momento.
```

Evita que el espectador mire el “tema” equivocado. Por ejemplo, en el caso de pareja, el foco no debe ser la relación sentimental, sino la diferencia entre razón declarada y causa afectiva.

## 2.7. `analizador_de_relaciones_retoricas`

Función principal:

```txt
Conectar subeventos entre sí mediante relaciones funcionales.
```

Ejemplos:

```txt
S1 prepara S2
S2 contrasta con S3
S3 permite abstraer S4
S4 justifica S5
```

## 2.8. `analizador_argumentativo`

Función principal:

```txt
Controlar claims, soportes, inferencias, matices y posibles objeciones.
```

Es clave para evitar afirmaciones simplistas como:

```txt
Todas tus razones son mentira.
Toda publicidad manipula emocionalmente.
Todo consumo premium es estatus.
```

## 2.9. `detector_de_esquemas_narrativos`

Función principal:

```txt
Crear plantillas repetibles para casos y ejemplos.
```

Por ejemplo:

```txt
estado afectivo → decisión → razón declarable
```

O en publicidad:

```txt
marca/producto → estado activado → símbolo usado → razón declarable → frase probable del consumidor
```

## 2.10. `extractor_de_macroestructura`

Función principal:

```txt
Extraer la forma común de varios casos.
```

Permite pasar de ejemplos sueltos a patrón general.

## 2.11. `analizador_de_metadiscurso`

Función principal:

```txt
Crear señales de orientación para el espectador.
```

Ejemplos:

```txt
Hasta aquí hemos visto...
Pero ahora la pregunta cambia...
Fíjate en algo...
Esto no significa que...
Ahora llevemos esto a publicidad...
```

## 2.12. `integrador_ACCD`

Función principal:

```txt
Compilar los elementos previos en una arquitectura coherente y validable.
```

Se usa sobre todo para cerrar matrices, patrones comunes y reglas finales.

# 3. Evento Cognitivo 1 — Caso ancla de reconocimiento

```yaml
evento_cognitivo_1:
  nombre: caso_ancla_de_reconocimiento
  frase_guia: "Esto pasa en las parejas"
  funcion_macro: hacer_visible_el_mecanismo_sin_definirlo
```

Este evento cognitivo instala el mecanismo en una situación reconocible. No debe explicar aún “racionalización afectiva”. Su trabajo es que el espectador vea la diferencia entre **lo que sostiene afectivamente una decisión** y **lo que se dice para justificarla**.

---

## Subevento 1.1 — Situación de pareja reconocible

```yaml
subevento_1_1:
  nombre: situacion_de_pareja_reconocible
  funcion: instalar_un_caso_que_la_audiencia_pueda_entender_de_inmediato
  modulo_MAANC:
    - modelador_de_situacion_cognitiva
    - analizador_intencional_atencional
  uso_del_modulo: >
    El modelador_de_situacion_cognitiva define el estado mental inicial del
    espectador: reconoce una situación de pareja sin necesitar teoría.
    El analizador_intencional_atencional fija el foco: no mirar "la pareja" como
    tema sentimental, sino como escenario donde se verá una doble capa.
```

**Operación cognitiva:** activar reconocimiento inmediato.

**Estado de entrada del espectador:**

```txt
“Entiendo esta situación; podría pasarle a alguien cercano.”
```

**Estado de salida del subevento:**

```txt
“Estoy dentro de un caso humano comprensible.”
```

```yaml
subevento_1_2:

    - detector_de_estructura_expositiva
  uso_del_modulo: >
    El analizador_de_moves_retoricos construye el gesto discursivo:
    la persona verbaliza una razón defendible.
    El detector_de_estructura_expositiva ayuda a formular esa razón de manera

```

**Ejemplo estructural:**

```txt
“No termino la relación porque creo que las relaciones se trabajan.”
```

**Operación cognitiva:** mostrar la capa verbal visible.

**Estado de salida del subevento:**

```txt
“Esta persona tiene una razón que suena madura, defendible o racional.”
```

## Subevento 1.3 — Capa afectiva no declarada

```yaml
subevento_1_3:

  funcion: mostrar_que_la_razon_declarada_no_agota_lo_que_sostiene_la_decision
  modulo_MAANC:
    - constructor_de_trayectoria_narrativa
    - modelador_de_situacion_cognitiva
  uso_del_modulo: >
    El constructor_de_trayectoria_narrativa produce el primer desplazamiento:
    de aceptar la razón declarada a sospechar que hay una capa más profunda.
    El modelador_de_situacion_cognitiva actualiza el estado del espectador:
    ahora distingue entre razón visible y fuerza afectiva posible.
```

**Capa posible:**

```txt
miedo a estar solo
apego
costumbre
identidad compartida
dependencia emocional
miedo a aceptar que algo terminó
```

**Operación cognitiva:** introducir disonancia.

**Estado de salida del subevento:**

```txt
“Quizá la razón dicha no explica todo lo que sostiene la decisión.”
```

## Subevento 1.4 — Contraste doble capa sin nombre técnico

```yaml
subevento_1_4:
  nombre: contraste_doble_capa_sin_nombre_tecnico
  funcion: hacer_visible_la_diferencia_entre_causa_afectiva_y_razon_declarable
  modulo_MAANC:
    - segmentador_funcional
    - analizador_de_relaciones_retoricas
  uso_del_modulo: >
    El segmentador_funcional separa dos responsabilidades: mostrar la razón
    declarada y mostrar la posible fuerza afectiva.
    El analizador_de_relaciones_retoricas conecta ambas como contraste:
    no son dos temas distintos, son dos capas de la misma decisión.
```

**Estructura del contraste:**

```txt
lo que dice:
  "me quedo por compromiso"

lo que quizá sostiene:
  miedo, apego, identidad, costumbre

resultado:
  el espectador ve que una razón puede justificar una decisión sin explicar toda su causa
```

# 5. Evento Cognitivo 3 — Formalización psicológica basada en teorías existentes

```yaml
evento_cognitivo_3:
  nombre: formalizacion_psicologica_basada_en_teorias_existentes
  frase_guia: "No necesitamos inventar un nombre: varias teorías explican partes del mecanismo"
  funcion_macro: construir_un_modelo_psicologico_respaldado_por_bibliografia
```

Su función es construir un **modelo psicológico compuesto**, apoyado en teorías existentes, que explique la estructura observada en los eventos anteriores.

El espectador entra con varios casos ya reconocidos y sale con un modelo psicológico suficientemente claro para entender los eventos posteriores:

```txt
estado afectivo / simbólico / identitario
→ orientación de la decisión
→ necesidad de explicación
→ razón declarable
→ estabilización o defensa de la decisión
```

El punto no es decir:

```txt
"Esto se llama racionalización afectiva."
```

Sino decir:

```txt
"Varias líneas de investigación psicológica permiten entender una estructura común:
no siempre accedemos con transparencia a lo que nos movió;
el afecto y la identidad pueden orientar la decisión;
y la razón verbal puede aparecer después como explicación, defensa o estabilización."
```

## Bibliografía base que sostiene el modelo

```yaml
bibliografia_base_evento_3:
  opacidad_introspectiva:
    autores_base:
      - Nisbett_y_Wilson_1977
    funcion_en_el_modelo: >
      Respaldar la idea de que las personas no siempre tienen acceso directo
      a los procesos que causaron sus decisiones.

  razonamiento_motivado:
    autores_base:
      - Kunda_1990
    funcion_en_el_modelo: >
      Mostrar que el razonamiento puede orientarse hacia conclusiones deseadas,
      protegidas o emocionalmente convenientes.

  juicio_intuitivo_y_razon_post_hoc:
    autores_base:
      - Haidt_2001
    funcion_en_el_modelo: >
      Mostrar que, en ciertos dominios, el juicio o la inclinación puede aparecer
      antes que la justificación racional explícita.

  disonancia_y_estabilizacion_postdecisional:
    autores_base:
      - Festinger_1957
      - Brehm_1956
    funcion_en_el_modelo: >
      Explicar cómo, después de decidir, el sujeto puede reorganizar valoraciones
      y razones para estabilizar la elección.

  choice_blindness_y_justificacion_reconstructiva:
    autores_base:
      - Johansson_Hall_Sikstrom_Olsson_2005
    funcion_en_el_modelo: >
      Mostrar que las personas pueden producir razones plausibles incluso cuando
      la relación entre elección y explicación no es transparente.

  primacia_afectiva_y_marcadores_somaticos:
    autores_base:
      - Zajonc_1980
      - Damasio_1994
      - Bechara_y_Damasio_2005
    funcion_en_el_modelo: >
      Evitar la falsa oposición emoción vs razón y mostrar que el afecto puede
      orientar la decisión antes o junto con la deliberación consciente.

  consumo_publicidad_afecto_y_cognicion:
    autores_base:
      - Batra_y_Ray_1986
      - Shiv_y_Fedorikhin_1999
    funcion_en_el_modelo: >
      Preparar el puente hacia publicidad mostrando que afecto y cognición
      interactúan en preferencias, consumo y evaluación de marcas.

  soportes_filosoficos_comparativos:
    autores_base:
      - Nietzsche
      - Wittgenstein
    funcion_en_el_modelo: >
      Usar a Nietzsche como sospecha filosófica sobre la transparencia del yo,
      la voluntad y la causa; y a Wittgenstein como apoyo comparativo para
      pensar cómo el lenguaje vuelve manejables estados internos.
    advertencia: >
      Estos autores no deben presentarse como prueba empírica psicológica, sino
      como marcos filosóficos comparativos.
```

## Subevento 3.1 — Del patrón observado al problema psicológico

```yaml
subevento_3_1:
  nombre: del_patron_observado_al_problema_psicologico
  funcion: convertir_los_casos_previos_en_una_pregunta_psicologica
  modulo_MAANC:
    - constructor_de_trayectoria_narrativa
    - detector_de_estructura_expositiva
    - analizador_de_metadiscurso
  uso_del_modulo: >
    El constructor_de_trayectoria_narrativa toma la salida del Evento Cognitivo 2
    y la convierte en entrada del modelo psicológico. El detector_de_estructura_expositiva
    organiza el paso de casos a problema. El analizador_de_metadiscurso marca la
    transición: no se va a nombrar una teoría nueva, se va a construir un modelo
    con teorías existentes.
```

**Operación cognitiva:** pasar de reconocimiento narrativo a problema psicológico.

**Estado de entrada del espectador:**

```txt
"He visto varios casos parecidos."
```

**Estado de salida del subevento:**

```txt
"Estos casos parecen apuntar a un problema psicológico general:
la diferencia entre lo que mueve una decisión y lo que después decimos sobre ella."
```

**Move retórico recomendado:**

```txt
No necesitamos inventar un nombre para esto.
Lo más sólido es mirar qué partes del fenómeno ya han sido estudiadas por la psicología.
```

## Subevento 3.2 — Opacidad introspectiva: no siempre sabemos por qué decidimos

```yaml
subevento_3_2:
  nombre: opacidad_introspectiva
  funcion: mostrar_que_la_razon_declarada_no_siempre_refleja_la_causa_real
  modulo_MAANC:
    - analizador_argumentativo
    - modelador_de_situacion_cognitiva
    - detector_de_estructura_expositiva
  bibliografia_base:
    - Nisbett_y_Wilson_1977
  uso_del_modulo: >
    El analizador_argumentativo construye el claim con soporte académico:
    las personas pueden explicar sus decisiones sin acceder completamente a los
    procesos que las produjeron. El modelador_de_situacion_cognitiva actualiza
    el estado del espectador: ya no debe tratar la introspección como una cámara
    transparente de la mente. El detector_de_estructura_expositiva distingue
    proceso real, experiencia subjetiva y explicación verbal.
```

**Claim del subevento:**

```txt
La razón que una persona da sobre su decisión puede ser coherente,
pero no necesariamente captura todo lo que causó la decisión.
```

**Función dentro del modelo:**

```txt
Abrir la separación entre:
- causa psicológica de la decisión
- explicación verbal de la decisión
```

**Frase estructural posible:**

```txt
A veces no mentimos.
A veces simplemente no tenemos acceso directo a todo lo que nos movió.
```

## Subevento 3.3 — Afecto, cuerpo e identidad como orientación decisional

```yaml
subevento_3_3:
  nombre: afecto_cuerpo_identidad_como_orientacion_decisional
  funcion: explicar_que_la_decision_puede_ser_orientada_por_estados_no_puramente_deliberativos
  modulo_MAANC:

    - detector_de_estructura_expositiva
    - analizador_intencional_atencional
  bibliografia_base:
    - Zajonc_1980
    - Damasio_1994
    - Bechara_y_Damasio_2005
  uso_del_modulo: >
    El modelador_de_situacion_cognitiva reconstruye la capa que orienta la
    decisión antes de la explicación: afecto, deseo, miedo, identidad, cuerpo,
```

# 6. Evento Cognitivo 4 — Diseño deliberado del patrón

```yaml
evento_cognitivo_4:
  nombre: diseno_deliberado_del_patron
  frase_guia: "Una cosa es que el patrón ocurra; otra cosa es que alguien aprenda a diseñarlo"
  funcion_macro: mostrar_que_el_modelo_de_doble_capa_puede_ser_construido_deliberadamente_por_entidades_politicas_o_comerciales
```

Este evento reemplaza la versión anterior del EC4 como simple “giro de diseño”. La función ya no es solo preparar una entrada abstracta a publicidad, sino **mostrar el patrón P1 en casos tangibles de diseño deliberado**.

El evento parte del modelo psicológico construido en el Evento Cognitivo 3:

```txt
orientación afectiva / implícita / identitaria
  → mueve o inclina la decisión

razón declarable
  → vuelve esa decisión explicable, defendible o aceptable
```

El EC4 debe mostrar que esa arquitectura puede ser intervenida desde fuera:

```txt
entidad diseñadora
  → mecanismo simbólico-emocional para tocar la capa orientadora
    → mecanismo discursivo-argumentativo para ofrecer, sugerir o dejar disponible una razón declarable
      → decisión experimentada como propia, razonable o defendible
```

Por eso, los ejemplos no deben funcionar como ejemplos sueltos. Deben funcionar como **dos realizaciones del mismo patrón de diseño**:

```txt
1. Campaña política
   → diseño explícito de orientación afectiva y razón declarable.

2. Marca de lujo
   → diseño simbólico de orientación afectiva y razón declarable sugerida o parcialmente delegada al consumidor.
```

# 7. Evento Cognitivo 5 — El juego de la influencia

El EC5 toma la estructura psicológica ya instalada —una decisión puede estar orientada por estados, símbolos, asociaciones y razones— y la formula como un juego con:

```txt

→ recursos limitados
→ riesgo de descubrimiento
→ condiciones terminales
→ intervención predecisional
→ producción de estado
→ razones escuchables
→ deseos humanos recurrentes

```

**Estado cognitivo de entrada:**

```txt

```

**Estado cognitivo de salida:**

```txt
El espectador comprende la influencia como un juego estructurado. Entiende que toda estrategia necesita una dirección, consume recursos, puede fracasar si esos recursos se agotan o si el plan se descubre, y opera principalmente antes de que la decisión aparezca como decisión visible.
```

```txt
2. El jugador agota sus recursos antes de conseguirlo.
3. El plan del jugador es descubierto.
```

**Operación cognitiva:** convertir restricciones dispersas en reglas del juego.

# 10. Regla operativa final

```txt
Cada evento cognitivo debe descomponerse en subeventos que no sean “partes del video”,
sino operaciones internas de transformación del espectador.
```

La arquitectura actualizada permite pasar de una estructura general del guion a una estructura escribible:

```txt
macrotrayectoria del video
→ eventos cognitivos
→ subeventos cognitivos
→ operaciones MAANC
→ escritura concreta del guion
```

La diferencia principal respecto de la versión anterior es que ahora la trayectoria termina en EC5:

```txt
caso
→ patrón
→ modelo psicológico
→ diseño deliberado
→ juego operativo de la influencia
```

# 11. Conclusión

Con esta actualización, el guion ya no depende de una secuencia de ocho eventos. La estructura final queda condensada en cinco Eventos Cognitivos:

- EC1 hace visible el mecanismo sin nombrarlo.
- EC2 muestra que el mecanismo no pertenece solo a la pareja, sino a muchas decisiones.
- EC3 formaliza psicológicamente el patrón con apoyo en teorías existentes.
- EC4 muestra que el patrón puede ser diseñado deliberadamente desde fuera.
- EC5 cierra el video convirtiendo ese patrón en el juego operativo de la influencia.

El antiguo EC5 como simple “transferencia publicitaria global” queda reemplazado por un EC5 terminal. Las funciones que antes se distribuían en eventos posteriores —demostración, retorno reflexivo y regla final memorable— ahora se condensan en la estructura interna del nuevo EC5.

Esta versión debe usarse como base actualizada para desarrollar, revisar o materializar el guion final del video.
