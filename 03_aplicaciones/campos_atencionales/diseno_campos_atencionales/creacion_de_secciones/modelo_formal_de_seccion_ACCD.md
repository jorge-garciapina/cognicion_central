# Modelo formal de sección para campos atencionales en la ACCD

## 0. Propósito del documento

Este documento formaliza el concepto de **sección** dentro de la ACCD como un modelo operativo para crear secciones en un campo atencional.

La sección se entiende como un **micro-sistema recurrente de producción atencional**. Su función no es únicamente agrupar temas, sino fijar una forma estable de transformar temas y materiales en construcciones conceptuales, y luego en manifestaciones codominiales compatibles con una o varias realizaciones.

La base del modelo es la ecuación de protocolo de la ACCD:

```txt
Pʳᵏ(Mⁱ(tⱼ), φₙ) = μʳᵏ(Mⁱ(tⱼ), φₙ)
```

y su versión operativa corregida:

```txt
Pʳᵏ(
  Combinar({Mⁱ(wₐ) | wₐ ∈ τⱼ}),
  φₙ
)
=
μʳᵏ
```

La corrección fundamental es:

```txt
Mⁱ no procesa un conjunto completo de materiales como bloque único.
Mⁱ procesa cada material wₐ por separado.
Después se combinan las estructuras cognitivas resultantes.
```

---

# 1. Definición central de sección

Una **sección** es una familia recurrente de manifestaciones generadas por una forma estable de construir corrientes cognitivas y proyectarlas hacia realizaciones compatibles.

En forma compacta:

```txt
sección =
familia recurrente de manifestaciones generadas por una forma estable
de construir corrientes cognitivas.
```

En forma desarrollada:

```txt
Una sección es un subespacio productivo dentro de una UOA o campo atencional
que fija una promesa de valor, una operación cognitiva recurrente,
un modo de procesar materiales, una forma de construcción conceptual,
un conjunto de instancias contextuales compatibles
y un conjunto de realizaciones posibles.
```

La sección responde a la pregunta:

```txt
¿Qué tipo recurrente de valor recibe la audiencia aquí,
con qué operación cognitiva,
bajo qué forma de tratamiento,
y en qué realizaciones puede manifestarse?
```

---

# 2. Distinciones fundamentales

## 2.1. Sección ≠ tema

Un tema responde:

```txt
¿De qué se habla?
```

Una sección responde:

```txt
¿Qué se hace con aquello de lo que se habla?
```

Ejemplo:

```txt
Tema:
  efecto Barnum

Secciones posibles:
  - desmontaje psicológico
  - caso histórico
  - aplicación práctica
  - comparación con personalización real
  - laboratorio de hooks
```

El mismo tema puede pasar por muchas secciones. Por eso, el tema no define la sección. La sección define una **operación recurrente sobre temas**.

---

## 2.2. Sección ≠ realización

Una realización responde:

```txt
¿En qué forma codominial aparece?
```

Ejemplos de realizaciones:

```txt
video_corto
carousel
newsletter
podcast
imagen
video_largo
```

La sección puede usar varias realizaciones.

Ejemplo:

```txt
Sección:
  "Desmontando mecanismos publicitarios"

Realizaciones compatibles:
  video_corto
  carousel
  newsletter
  podcast
```

La sección define la lógica recurrente. La realización define la materialidad de salida.

---

## 2.3. Sección ≠ manifestación

Una manifestación es una pieza concreta:

```txt
un video corto específico
un carousel específico
una edición específica de newsletter
un episodio específico de podcast
```

La sección es la familia que permite producir muchas manifestaciones.

```txt
Sección:
  Desmontando mecanismos publicitarios

Manifestaciones:
  - video sobre efecto Barnum
  - carousel sobre curiosidad
  - newsletter sobre precio como señal
  - podcast sobre confianza bajo riesgo
```

---

## 2.4. Sección ≠ UOA

Una UOA es una organización local de atención:

```txt
canal de YouTube
cuenta de TikTok
newsletter
perfil de Instagram
podcast
comunidad
```

La sección vive dentro de una UOA o puede ser compartida por varias UOA.

```txt
Campo Atencional
  → UOA
    → Secciones
      → Manifestaciones
```

La UOA selecciona un subespacio local. La sección define una operación recurrente dentro de ese subespacio.

# 3. Base formal de la ecuación de protocolo

Partimos de la ecuación:

```txt
Pʳᵏ(Mⁱ(tⱼ), φₙ) = μʳᵏ(Mⁱ(tⱼ), φₙ)
```

Donde:

```txt
tⱼ
  = tema

Mⁱ
  = módulo MAANC

Mⁱ(tⱼ)
  = construcción conceptual producida por el módulo Mⁱ

φₙ
  = instancia contextual

Pʳᵏ
  = protocolo de la realización rₖ

μʳᵏ
  = manifestación codominial producida
```

Sin embargo, cuando un tema está asociado a varios materiales, no se debe aplicar el módulo al conjunto como si fuera una unidad indiferenciada.

Se define:

```txt
τⱼ = {w₁, w₂, ..., w_q}
```

Donde:

```txt
τⱼ
  = conjunto de materiales asociados al tema tⱼ

wₐ
  = material individual
```

El procesamiento correcto es:

```txt
Mⁱ(wₐ) = mⁱ_{j,a}
```

para cada material `wₐ`.

Luego se combinan los procesamientos individuales:

```txt
mⁱⱼ = Combinar({Mⁱ(wₐ) | wₐ ∈ τⱼ})
```

Finalmente:

```txt
Pʳᵏ(mⁱⱼ, φₙ) = μʳᵏ(mⁱⱼ, φₙ)
```

La forma completa queda:

```txt
Pʳᵏ(
  Combinar({Mⁱ(wₐ) | wₐ ∈ τⱼ}),
  φₙ
)
=
μʳᵏ
```

Esta es la fórmula base para entender cómo una sección produce manifestaciones.

# 6. Definición formal de sección

Una sección puede definirse como:

```txt
σ = (Tσ, Wσ, Cσ, Vσ)
```

Donde:

```txt
σ
  = sección

Tσ
  = conjunto de temas admitidos por la sección

Wσ
  = política de materiales admitidos

Cσ
  = corriente cognitiva recurrente esperada por la sección

Vσ
  = promesa de valor / operación de valor recurrente
```

La extensión de una sección es:

```txt
Ext(σ) =
{
  μʳᵏ(
    Combinarσ({Mⁱ(wₐ) | wₐ ∈ τⱼ}),
    φₙ
  )
  |
  tⱼ ∈ Tσ,
  τⱼ asociado a tⱼ,
  Mⁱ ∈ Mσ,
  φₙ ∈ Φσ,
  rₖ ∈ Rσ
}
```

En lenguaje natural:

```txt
La sección contiene todas las manifestaciones que pueden producirse
cuando se toman temas admitidos por la sección,
se procesan sus materiales mediante los módulos MAANC fijados,
se combinan las estructuras cognitivas resultantes,
se acoplan con instancias contextuales compatibles
y se proyectan hacia realizaciones admitidas.
```

# 7. La sección como micro-sistema de producción

La sección no es solo un contenedor. Es un micro-sistema.

Debe fijar:

```txt
promesa recurrente
operación cognitiva
operación atencional
tipo de corriente cognitiva
función de eventos cognitivos
criterio de inclusión temática
criterio de inclusión de materiales
modo de procesamiento MAANC
regla de combinación
instancias contextuales compatibles
realizaciones compatibles
ritmo de producción
estilo de entrada
tipo de evidencia
modo de cierre
criterios de validación
```

La sección funciona así:

```txt
Campo Atencional
  → UOA
    → Sección
      → Molde productivo
        → Construcción conceptual
          → Protocolo
            → Manifestaciones isomorfas
```

La palabra clave es:

```txt
isomorfismo
```

Las piezas de una misma sección pueden tratar temas distintos, pero conservan una forma funcional reconocible.

Ejemplo:

```txt
Sección:
  "Mecanismo en 5 pasos"

Tema 1:
  curiosidad publicitaria

Tema 2:
  precio como señal de valor

Tema 3:
  efecto Barnum

Forma recurrente:
  situación inicial
    → mecanismo oculto
      → ejemplo visible
        → inferencia
          → aplicación práctica
```

La sección existe porque esa forma se repite con variación.

# 8. Componentes del modelo formal de sección

## 8.1. Identidad de sección

Define dónde vive la sección.

```yaml
id_seccion:
nombre:
descripcion:
campo_atencional_origen:
UOA_de_pertenencia:
```

Ejemplo:

```yaml
id_seccion: SEC_DESMONTAJE_MECANISMOS_PUBLICITARIOS
nombre: "Desmontando mecanismos publicitarios"
campo_atencional_origen: campo_atencional_publicidad
UOA_de_pertenencia: UOA_tiktok_publicidad_psicologica
```

---

## 8.2. Promesa de valor

La sección debe decir qué valor recurrente entrega.

```yaml
promesa_de_valor:
  tipo:
  formulacion:
  beneficio_para_audiencia:
```

Ejemplo:

```yaml
promesa_de_valor:
  tipo: comprension_aplicable
  formulacion: >
    Mostrar el mecanismo psicológico oculto detrás de una pieza,
    campaña o estrategia publicitaria.
  beneficio_para_audiencia: >
    La audiencia aprende a reconocer mecanismos que antes operaban
    de forma invisible.
```

La promesa de valor distingue una sección de un simple grupo temático.

---

## 8.3. Operación cognitiva recurrente

Aquí se fija qué tipo de operación realiza la sección.

```yaml
operacion_cognitiva_recurrente:
  tipo:
  descripcion:
```

Ejemplos de operaciones:

```txt
desmontar
comparar
diagnosticar
traducir
aplicar
historizar
clasificar
argumentar
ejemplificar
inferir
reencuadrar
```

Ejemplo:

```yaml
operacion_cognitiva_recurrente:
  tipo: desmontaje
  descripcion: >
    Tomar una manifestación publicitaria o principio psicológico
    y revelar la estructura que explica su funcionamiento.
```

---

## 8.4. Operación atencional

La sección también debe decir cómo administra atención.

```yaml
operacion_atencional:
  tipo:
  descripcion:
```

Ejemplos:

```txt
captacion_por_curiosidad
reconocimiento_autorreferencial
clarificacion
tension_conceptual
sorpresa
acumulacion
recompensa_inferencial
```

Ejemplo:

```yaml
operacion_atencional:
  tipo: revelacion_de_mecanismo_oculto
  descripcion: >
    La sección captura atención mostrando que detrás de algo cotidiano
    existe una estructura no evidente.
```

---

## 8.5. Temas admitidos

```yaml
Tσ:
  criterio_de_inclusion:
  criterio_de_exclusion:
  temas_admisibles:
```

Ejemplo:

```yaml
Tσ:
  criterio_de_inclusion: >
    Temas que puedan formularse como mecanismo psicológico,
    publicitario, narrativo o atencional identificable.
  criterio_de_exclusion: >
    Temas meramente descriptivos que no permitan revelar una operación.
  temas_admisibles:
    - curiosidad_publicitaria
    - precio_como_senal
    - efecto_Barnum
    - reciprocidad_comercial
    - propiedad_psicologica
```

---

## 8.6. Corriente cognitiva recurrente

La sección debe fijar qué tipo de corriente espera producir.

```yaml
Cσ:
  tipo_de_corriente:
  eventos_recurrentes:
```

Ejemplo:

```yaml
Cσ:
  tipo_de_corriente: mecanismo_en_5_pasos
  eventos_recurrentes:
    e1:
      funcion: situacion_inicial
      descripcion: presentar el fenómeno visible
    e2:
      funcion: mecanismo_oculto
      descripcion: revelar la operación que explica el fenómeno
    e3:
      funcion: ejemplo_visible
      descripcion: mostrar un caso donde el mecanismo se observa
    e4:
      funcion: inferencia
      descripcion: extraer el principio general
    e5:
      funcion: aplicacion_practica
      descripcion: mostrar cómo usar o reconocer el mecanismo
```

Esta es una de las piezas más importantes del modelo.

La sección fija una forma de corriente. El tema cambia. El material cambia. La realización puede cambiar. Pero la corriente recurrente se conserva.

## 8.7. Realizaciones compatibles

```yaml
Rσ:
  realizaciones_compatibles:
  realizacion_dominante:
  regla_de_adaptacion:
```

Ejemplo:

```yaml
Rσ:
  realizaciones_compatibles:
    - video_corto
    - carousel
    - newsletter
  realizacion_dominante: video_corto
  regla_de_adaptacion: >
    La misma corriente cognitiva debe poder proyectarse en bloques,
    láminas o secciones textuales sin perder su forma funcional.
```

# 10. Relación con construcción conceptual

La sección no produce directamente la manifestación. Primero produce o condiciona la construcción conceptual.

La cadena es:

```txt
tema
  → materiales asociados
    → procesamiento MAANC por separado
      → estructuras cognitivas resultantes
        → combinación
          → construcción conceptual integrada
            → protocolo
              → manifestación codominial
```

La sección fija cómo ocurre este tramo:

```txt
materiales asociados
  → procesamiento MAANC por separado
    → combinación
      → construcción conceptual integrada
```

Por eso la sección es una pieza clave antes del protocolo.

---

# 11. Regla de no colapso de niveles

El modelo de sección debe respetar las siguientes distinciones:

```txt
tema ≠ sección
sección ≠ UOA
UOA ≠ campo atencional
realización ≠ sección
manifestación ≠ sección
construcción conceptual ≠ instancia contextual
protocolo ≠ construcción conceptual
material individual ≠ conjunto de materiales
procesamiento individual ≠ construcción conceptual integrada
```

Estas distinciones evitan errores de diseño.

---

# 12. Definición final consolidada

```txt
Una sección es un micro-sistema productivo dentro de una UOA o campo atencional
que fija una promesa de valor, una operación cognitiva recurrente,
una forma de corriente cognitiva, una política de procesamiento de materiales,
un operador de combinación, un conjunto de instancias contextuales compatibles
y un conjunto de realizaciones posibles, con el fin de producir una familia
reconocible de manifestaciones codominiales.
```

Esta definición condensa tres ideas anteriores:

```txt
1. Sección como contenedor funcional recurrente.
2. Sección como micro-sistema de producción.
3. Sección como adaptador contextual.
```

Y las integra con la ecuación de protocolo ACCD:

```txt
Pʳᵏ(
  Combinar({Mⁱ(wₐ) | wₐ ∈ τⱼ}),
  φₙ
)
=
μʳᵏ
```

La sección se convierte, así, en una unidad formal para diseñar producción recurrente dentro de campos atencionales.
